# GitHub

Зачем человеку: **бэкап** (ноутбук сломался — всё на GitHub), **кнопка «отменить»** (Claude сломал — вернулись к рабочей версии),
**обновления** пакета и завода приходят оттуда же. Объясняй так: коммит — «сохранился в игре», пуш — «отправил сохранение в облако».

## 1. Аккаунт (делает человек, ты ведёшь)
1. Открой ему github.com/signup. Почта — та, к которой есть доступ с телефона. Пароль — длинный, записать в менеджер паролей
   или в блокнот дома, **не в чат и не в файлы**. Имя пользователя — латиницей, без лишних цифр: оно будет в ссылках.
2. GitHub пришлёт код на почту — ввести. Включить вход по телефону или приложению (2FA) — GitHub попросит сам, это нормально.
Пароль и коды не вводишь ты — только человек.

## 2. Подключить компьютер
- **Windows:** с Git for Windows уже стоит Git Credential Manager: при первом `git push` откроется окно входа в GitHub в браузере —
  человек жмёт «Sign in with your browser» → «Authorize». Больше ничего не нужно.
- **Mac:** нужен `gh`. Нет `gh --version` → скачай установщик с github.com/cli/cli/releases (файл `gh_*_macOS_universal.pkg`),
  открой его (`open <файл>`), человек жмёт «Продолжить» → «Установить». Потом `gh auth login --hostname github.com --git-protocol https --web`
  и `gh auth setup-git`: в чате появится код из 8 знаков, человек вводит его на открывшейся странице и жмёт «Authorize».

## 3. Бэкап папки Projects
1. Проверь `.gitignore` в Projects: там `.env`, видео, `node_modules`. Ключей в папке быть не должно (`proverka.py` это проверяет).
2. `git init -b main`, `git config user.name "<имя>"`, `git config user.email "<имя>@users.noreply.github.com"` — чтобы почта не светилась.
3. Первый коммит: `git add -A && git commit -m "Цифровой мозг: начало"`.
4. Репозиторий — **только приватный**:
   - есть `gh`: `gh repo create projects --private --source . --push`;
   - нет: человек на github.com → «New» → имя `projects` → **Private** → галочки не ставить → «Create», присылает ссылку,
     ты: `git remote add origin <ссылка>` и `git push -u origin main` (на Windows откроется окно входа — см. выше).
5. Доказательство: `git log -1` и ссылка на репозиторий, человек открывает и видит свои файлы и замок «Private».

## 4. Каждый день
- Сохраняй версию после рабочего шага (что-то заработало): `git add -A && git commit -m "<что сделали>"`. Перед большой переделкой — тоже.
- Отправляй в облако в конце работы: `git push`. Человек сказал «сделай бэкап» — коммит и пуш сразу.
- **Откат:** покажи `git log --oneline -15` словами («вчера: лендинг работал»), человек выбирает. Перед откатом сохрани текущее
  (`git commit` или ветка `do-otkata`), потом верни нужное: один файл — `git restore --source <коммит> <файл>`, всё — новой веткой.
  Предупреди, что отменится всё после той версии. Без его «да» не откатывай.
- Публичный репозиторий, удаление репозитория, `push --force` — только после его «да».
